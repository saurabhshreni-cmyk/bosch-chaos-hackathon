Pitstop Chaos Agent

Team No. 28 | AI-driven chaos engineering in an isolated Docker sandbox

Application Dependencies

Web app → three HTTP APIs → SQL Server; domain events travel through RabbitMQ to Workshop projection, invoice, notification and audit workers. Time service emits daily events; mail and Seq support delivery and logs. Map is semi-automatically documented and manually reviewed.

Decision And Evidence Pipeline

Dependency map + healthy baseline → local Ollama / Qwen ranked plan
Strict schema + fixed tool registry → bounded PowerShell fault runner
Page probes + recovery verification → statistical anomalies → AI findings
JSON / CSV evidence → live dashboard + ranked report + heuristic probe score
ComponentResponsibility
AI planner / analyzerRanks every allowed experiment with reasons; interprets measured anomaly IDs and suggests fixes. Output is untrusted and validated. It cannot issue arbitrary shell commands.
Safety controllerLocal Docker and checkout ownership checks; healthy preflight; one fault at a time; duration watchdog; unrelated-module latency / shared-blast-radius thresholds; STOP file; recovery gate.
Experiment toolsAPI, SQL or broker crash; 500 ms Workshop network delay. Combined profile: API crash with at most two read-load connections, 10 GETs/sec, 30 sec maximum.
DashboardLoopback-only Node server with request validation. Live health, lifecycle, ranked plans, charts, dependencies, findings, retained runs, confirmation and emergency STOP.

Scope And Limits

Container restart restores services without deleting database volumes. Read probes detect HTTP-200 offline fallbacks but do not prove write correctness or message durability. AI findings are hypotheses for human review. The score is a disclosed experiment-specific heuristic, not an AI-certified SLA. No production or shared systems are targeted.
